# 사용자 페르소나 정의서

> AI가 만든 가설 초안이며 실제 사용자 조사 결과가 아니다. 사용자가 검토·수정한 뒤 기획 근거로 사용한다.

## 핵심 사용자

- 주요 독자: 미완결 위험 없이 좋아하는 웹소설을 실물로 소장하려는 20~30대 독자
- 주요 작가: 소수의 충성 독자를 보유했지만 직접 출판·재고 관리가 어려운 독립 웹소설 작가
- 운영 사용자: 펀딩 결과와 책 제작 주문을 확인하고 처리하는 서비스 관리자

## 작가 페르소나 5명

### W1. 김하린 — 퇴근 후 연재하는 신인 작가

- 29세 직장인, 평일 저녁에 로맨스 판타지를 연재한다.
- 첫 장편이라 독자가 기다리는지 확신하지 못해 완결 의지가 자주 흔들린다.
- 목표: 소장본 수요를 확인하며 첫 번째 부를 완결하고 싶다.
- 불편: 조회 수만으로 실제 구매 의사를 알기 어렵다.
- 사용 환경: PC로 집필하고 모바일로 펀딩 현황을 확인한다.
- 필요 기능: 부 진행 상태, 유료 펀딩 인원, 목표 달성률, 출판 가능 조건 안내

### W2. 박도윤 — 소규모 팬덤을 가진 독립 작가

- 34세 프리랜서 작가, 이전 작품 독자 약 300명이 있다.
- 선입금 폼, 인쇄소 견적, 배송지 정리를 직접 처리한 경험이 있다.
- 목표: 재고와 배송 업무 없이 팬에게 소장본을 제공하고 싶다.
- 불편: 연재 플랫폼과 인쇄·주문 서비스가 분리되어 반복 작업이 많다.
- 사용 환경: PC 중심으로 작품과 주문 현황을 관리한다.
- 필요 기능: 완결 작품의 펀딩 개설, 한 권 예상 분량 확인, 주문 자동 전환, 제작 상태 일괄 조회

### W3. 이수민 — 부 단위로 연재하는 장기 작가

- 31세 전업 작가, 한 작품을 1부·2부처럼 여러 부로 나누어 연재한다.
- 전체 완결까지 기다리면 소장본 출시가 너무 늦어진다.
- 목표: 각 부 완결 시점마다 독자에게 소장본을 제공하고 싶다.
- 불편: 전체 완결과 부 완결을 같은 상태로 처리하는 서비스가 불편하다.
- 사용 환경: PC 집필, 모바일 독자 반응 확인
- 필요 기능: 연재 중·부 완결·전체 완결 상태 구분, 부별 회차 범위와 권당 목표 글자 수 지정

### W4. 최우진 — 완결작을 보유한 재출판 희망 작가

- 37세, 과거 플랫폼에 완결한 판타지 소설이 있지만 종이책 출간 경험은 없다.
- 예전 독자가 아직 소장본을 원하는지 알 수 없어 제작을 미루고 있다.
- 목표: 재고 없이 완결작의 현재 수요를 검증하고 싶다.
- 불편: 최소 제작 수량을 작가가 먼저 부담하는 것이 두렵다.
- 사용 환경: PC로 기존 원고를 정리하고 펀딩 현황을 확인한다.
- 필요 기능: 완결작 등록, 목표 수량 설정, 실패 시 자동 환불 상태

### W5. 정서윤 — 필명 노출에 민감한 장르 작가

- 26세 취미 작가, 필명으로만 활동하며 소수 독자와 교류한다.
- 직접 통판하면 실명·주소 등 개인정보가 노출될까 걱정한다.
- 목표: 개인 배송 업무 없이 필명으로 소장본을 제공하고 싶다.
- 불편: 제작·결제·배송 문의를 혼자 감당하기 어렵다.
- 사용 환경: 모바일로 독자 반응을 자주 확인하고 PC로 집필한다.
- 필요 기능: 필명 중심 표시, 펀딩·제작 상태의 명확한 안내

## 독자 페르소나 6명

### R1. 윤지아 — 미완결 경험으로 결제에 신중한 독자

- 28세 직장인, 연재 중단 작품에 여러 번 결제한 경험이 있다.
- 재미있는 신작을 발견해도 완결 가능성을 먼저 확인한다.
- 목표: 작품을 응원하되 미완결이면 안전하게 환불받고 싶다.
- 불편: 작가의 연재 상태와 출판 조건을 알기 어렵다.
- 사용 환경: 출퇴근 중 모바일로 회차를 읽는다.
- 필요 기능: 연재·부 완결·전체 완결 표시, 펀딩 기한, 실패·환불 조건 안내

### R2. 강민호 — 한정판 소장 욕구가 강한 독자

- 32세 직장인, 좋아하는 작품의 단행본과 굿즈를 모은다.
- 전자책으로 읽은 작품도 만족도가 높으면 종이책을 다시 구매한다.
- 목표: 좋아하는 작품을 품질 좋은 실물 책으로 소장하고 싶다.
- 불편: 소장본 제작 여부를 여러 SNS에서 찾아야 한다.
- 사용 환경: 모바일 열람, PC로 책 사양과 펀딩 상세 확인
- 필요 기능: 판형·표지·포함 회차·수량, 제작 진행 상태 표시

### R3. 오세진 — 예산을 계획해서 참여하는 독자

- 25세 취업준비생, 월 취미 예산이 정해져 있다.
- 펀딩 금액이 언제 결제되고 어떤 경우 환불되는지를 중요하게 본다.
- 목표: 추가 비용이나 장기 미배송 위험 없이 참여하고 싶다.
- 불편: 목표 미달·완결 실패 시 처리 방식이 불명확하면 결제하지 않는다.
- 사용 환경: 모바일 중심
- 필요 기능: 모의 결제 금액, 목표 수량, 남은 기간, 환불 상태의 쉬운 문구

### R4. 한예린 — 완결 후 몰아보는 독자

- 30세 직장인, 연재를 기다리는 것이 힘들어 부 완결 후 한 번에 읽는다.
- 완독한 작품 중 다시 읽고 싶은 작품만 소장한다.
- 목표: 완결 작품을 빠르게 찾고 읽은 뒤 책으로 주문하고 싶다.
- 불편: 연재작과 완결작이 섞여 있으면 탐색 시간이 길어진다.
- 사용 환경: 태블릿·모바일로 장시간 읽는다.
- 필요 기능: 완결 상태 필터, 회차 이동, 읽기 편한 글자 크기와 여백

### R5. 임태경 — 작가의 완결을 돕고 싶은 초기 후원 독자

- 27세, 신인 작가 작품을 찾아 읽고 주변에 추천하는 것을 좋아한다.
- 단순 후원보다 완결 후 실물 책을 받는 방식에 매력을 느낀다.
- 목표: 자신의 참여가 완결과 출판에 얼마나 기여하는지 확인하고 싶다.
- 불편: 펀딩 참여 이후 진행 상황이 보이지 않으면 불안하다.
- 사용 환경: 모바일로 자주 진행률 확인
- 필요 기능: 현재 참여 수, 목표 달성률, 완결 조건, 주문 전환 상태 표시

### R6. 서나래 — 독자로 시작해 첫 연재를 준비하는 예비 작가

- 27세 직장인, 출퇴근길에는 웹소설을 읽고 퇴근 후에는 개인 원고를 작성한다.
- 다른 작가의 작품을 읽고 추천·즐겨찾기하다가 완성한 원고를 직접 연재해 보고 싶어졌다.
- 목표: 익숙한 독자 화면은 그대로 사용하면서 작가 기능을 활성화해 첫 작품을 미공개 상태로 등록하고 싶다.
- 불편: 독자 서비스와 작가 서비스가 분리되거나 별도 계정을 다시 만들어야 하면 진입 과정이 어렵게 느껴진다.
- 사용 환경: 모바일로 작품 탐색, PC로 작품·부·회차 작성
- 필요 기능: 이해하기 쉬운 작가 권한 활성화 진입점, 독자 기능을 포함하는 누적 메뉴, 첫 미공개 작품 등록 안내
- 데모 고려: 과제에서는 역할별 고정 체험 회원을 사용하므로 전환 시 기존 독자 추천·즐겨찾기는 이어지지 않으며, 실서비스에서는 동일 회원의 권한 승격으로 유지해야 한다.

## 관리자 페르소나

### A1. 이지훈 — 주문 제작 현황을 관리하는 운영자

- 35세 서비스 운영자, 성공한 펀딩이 주문으로 정상 전환됐는지 매일 확인한다.
- 목표: 서비스 현황을 빠르게 파악하고 제작 지연 없이 주문 상태를 처리하고 싶다.
- 불편: 작품·펀딩·주문 데이터가 분리되어 있으면 누락 여부를 찾기 어렵다.
- 사용 환경: PC 중심
- 필요 기능: 핵심 운영 통계, 전체 주문 검색·필터, 순차 상태 변경, CSV·JSON 내보내기

## 공통 UX 판단

- 독자 화면은 모바일 우선으로 구성하고 작품 상태와 펀딩 조건을 쉬운 문구로 표시한다.
- 작가 화면은 PC에서 작품·회차·펀딩 상태를 한 번에 관리하도록 구성한다.
- 관리자 화면은 PC에서 핵심 수치와 처리할 주문을 우선 확인하도록 구성한다.
- 웹소설 탐색이 서비스 본체이므로 모든 역할이 같은 공개 콘텐츠를 보고, 역할별로는 관리 메뉴만 추가한다. 역할마다 다른 홈을 만들면 플랫폼이 아니라 관리 도구처럼 보이기 때문이다.
- 작품 연재 상태와 공개 여부를 분리하고, 미공개 작품은 소유자와 관리자만 조회한다. 관리자도 타 작가 작품은 수정하지 못한다.
- 가입·인증 없이도 작품·참여·주문 소유자를 구분하기 위해 역할별 고정 체험 회원 1명을 두고 세션에 연결한다. 같은 역할로 다시 들어오면 기존 데이터를 이어서 확인할 수 있다.
- 권한은 `독자 < 작가 < 관리자`로 누적한다. 작가는 독자로도 읽기·펀딩하기 때문에 별도 독자 계정이 필요하지 않다.
- R6처럼 독자로 시작한 사용자가 작가가 될 수 있다는 흐름을 `작가 권한 활성화 체험`으로 보여준다. 작가는 독자 기능을 포함하므로 되돌리기 버튼은 두지 않는다.
- 독자→작가 전환은 다른 고정 체험 계정이므로 즐겨찾기·추천(및 향후 댓글)이 이어지지 않는다. 데이터 연속성 확인이 필요할 때는 역할 전환 없이 같은 역할로 이어 보는 것을 권장한다.
- 실서비스에서는 펀딩 피해 방지를 위해 작가 전환에 엄격한 인증이 필요하지만, 과제에서는 체험만 제공한다.
- 장기 연재 독자가 어느 부까지 끝났는지 바로 알 수 있도록 `1부 완결`, `2부 완결`처럼 부 번호를 표시한다.
- `목표 달성`만으로 출판하지 않고 `부 완결 또는 전체 완결`과 `한 권 예상 분량` 조건을 함께 보여준다.
- 모의 결제임을 명시하고 성공·실패·환불·주문 전환 상태를 혼동하지 않게 구분한다.
- 이번 과제에서는 인증·실제 결제·정산·배송·알림·댓글을 구현하지 않는다.

## MVP 우선순위

1. 독자의 작품 목록·상세·회차 열람
2. 작가의 작품·회차 생성과 수정, 완결 상태 변경
3. 독자의 소장본 펀딩 참여와 모의 결제
4. 완결·목표 달성 판정과 주문 전환
5. 관리자의 주문 제작 상태 조회·변경과 운영 통계
6. 주문 CSV·JSON 내보내기
