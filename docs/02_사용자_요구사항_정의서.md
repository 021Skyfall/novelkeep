# 사용자 요구사항 정의서

> `docs/01_사용자_페르소나.md`를 바탕으로 AI가 작성한 가설 초안이다. 실제 사용자 조사 결과가 아니며 사용자 승인 후 구현 기준으로 사용한다.

## 1. 서비스 목표

- 독자는 웹소설을 온라인으로 읽고, 완결이 보장된 작품의 소장본 펀딩에 안전하게 참여한다.
- 작가는 연재 콘텐츠를 관리하고 실제 소장 수요를 확인해 재고 부담 없이 출판을 결정한다.
- 관리자는 펀딩 성공 건만 전환된 책 제작 주문과 서비스 통계를 확인하고 제작 상태를 관리한다.

## 2. 사용자 역할

### 용어 구분

- `부`: 여러 회차를 묶는 이야기 구조이자 소장본 한 권의 출판 단위다. 1부=1권, 2부=2권으로 대응한다.
- 단권 작품은 화면에는 부를 표시하지 않지만 내부적으로 기본 부 `본편`을 사용한다.
- `권`: 실제 책 제작 단위로, 현재 정책에서는 부와 1:1이다. 한 부 안에서 다시 여러 권으로 나누지 않는다.
- 글자 수는 실제 조판 전 예상 분량으로만 사용한다.

### 주요 사용자

- 독자: 미완결 작품의 구매 위험을 피하면서 좋아하는 작품을 실물로 소장하려는 20~30대
- 모든 회원의 기본 권한이며 작가와 관리자도 독자 기능을 함께 사용한다.
- 대표 페르소나: R1 윤지아, R6 서나래(독자→작가 전환)

### 보조 사용자

- 작가: 소규모 팬덤은 있지만 직접 인쇄·재고·배송을 관리하기 어려운 독립 작가
- 데모에서는 독자가 `작가 권한 활성화 체험`으로 AUTHOR 고정 회원을 선택하면 독자 기능에 작가 기능이 누적된다.
- 실서비스에서는 펀딩 피해 방지를 위해 작가 전환에 본인·활동 인증이 필요하지만 과제에서는 구현하지 않는다.
- 대표 페르소나: W2 박도윤, R6 서나래(예비 작가)

### 운영 사용자

- 관리자: 펀딩과 주문 전환 결과를 확인하고 제작 상태와 운영 데이터를 관리하는 담당자
- 독자·작가·관리자 기능을 모두 사용할 수 있다. 다만 다른 고정 AUTHOR 회원의 작품은 소유권이 다르므로 자동으로 수정하지 않는다.
- 대표 페르소나: A1 이지훈

### 데모 환경 원칙

- 회원가입과 로그인은 구현하지 않는다. 콘텐츠·펀딩·주문 핵심 흐름 검증에 집중하기 위해서다.
- 작품 소유자와 펀딩·주문 소유자를 구분하기 위한 최소 회원 데이터는 저장한다.
- 별도 랜딩페이지에서 독자·작가·관리자 체험 모드를 선택한다. 역할을 고르기 전에는 공개 콘텐츠에도 접근하지 않는다.
- 역할별 고정 체험 회원을 앱 시작 목 데이터로 하나씩 생성하고 이후 같은 회원을 재사용한다.
- 역할 선택 시 세션에 고정 `memberId`와 역할을 저장한다. 역할은 기능 범위, 회원 ID는 데이터 소유권이다.
- 선택 이후 모든 역할은 같은 공개 콘텐츠 원본을 조회한다. 역할별로 작품을 복제하지 않는다.
- `역할 변경`은 기존 세션을 무효화하고 랜딩에서 다른 고정 체험 회원을 다시 선택한다.
- 권한은 `독자 < 작가 < 관리자`로 누적하며 역할 선택 후 같은 콘텐츠 메인으로 이동한다.
- 독자는 `작가 권한 활성화 체험`으로 작가 고정 회원으로 전환할 수 있다. 작가→독자 되돌리기 버튼은 두지 않는다.
- 독자→작가 전환 시 세션의 고정 체험 회원이 바뀌므로 즐겨찾기·추천(및 향후 댓글)은 이어지지 않는다. 데이터 연속성 테스트 중에는 역할 전환을 권장하지 않는다.
- 독자 화면을 다시 보려면 `역할 변경` 후 랜딩에서 독자를 선택한다.
- 이 기능은 실제 인증이나 보안을 대신하지 않는다.
- 결제·환불·정산·배송은 실제 연동 없이 화면과 데이터 상태로 모의 처리한다.
- 목 데이터는 전체를 미리 만들지 않고 작품 → 부·회차 → 펀딩 → 주문 구현 단계에 맞춰 한 초기화 클래스에 추가한다. 개발·데모 앱 시작 시 `create-drop` 스키마에 자동 적재한다.

## 3. 기능 요구사항

우선순위는 `필수(Must)`, `가능하면 구현(Should)`, `범위 밖(Won't)`으로 구분한다.

| RQ-R09 | 부 완결과 목표 부수 달성이 출판 조건임을 참여 전에 확인할 수 있어야 한다. 분량은 안내만 한다. | Must | R1, R3 |

| RQ-R12 | 회원은 공개 작품을 내 즐겨찾기에 추가·해제하고 모아서 볼 수 있어야 한다. | Should | R1, R4 |

| RQ-W09 | 작가는 펀딩 참여 수, 달성률과 출판 가능 여부를 한 화면에서 확인할 수 있어야 한다. | Must | W1, W2, W4 |
| RQ-W10 | 작가는 펀딩을 마감하고 성공·실패 조건 판정을 실행할 수 있어야 한다. | Must | W2, W4 |
| RQ-W11 | 작가는 자신의 성공한 펀딩에서 생성된 주문 수와 제작 상태를 확인할 수 있어야 한다. | Must | W2 |

## 5. 상태 정의

### 작품 상태

연재 상태: `SERIALIZING(연재 중) → COMPLETED(전체 완결)` — 부 완결과 구분한다.

공개 여부: `PUBLIC(공개)`, `PRIVATE(미공개)` — 새 작품 기본값은 `PRIVATE`

작품(부 제외)에서 쓰는 표시 조합은 **공개·미공개·연재 중·전체 완결**이다.

조회 범위: 공개 탐색에서는 독자·작가가 `PUBLIC`만 보고 관리자는 전체를 조회한다. 작가는 내 작품 관리에서 본인 `PRIVATE`를 확인하며, 수정·삭제는 소유자만 가능하다.

### 부 상태

`UNPUBLISHED(미공개) → SERIALIZING(연재 중) → COMPLETED(부 완결)`

미공개 권은 소유자·관리자만 상세·열람에 포함되며, 독자에게는 해당 권 자체가 보이지 않는다.  
부 상태는 회차 공개 여부와 **독립**이다. 회차를 미공개로 바꿔도 부 완결이 연재 중으로 자동 내려가지 않는다.  
부를 완결로 **저장**할 때만 해당 부 회차가 모두 공개인지 검사한다.

### 회차 상태

`UNPUBLISHED(미공개) ↔ PUBLISHED(공개)`

### 펀딩 상태

`OPEN(진행 중) → SUCCESS(성공) 또는 FAILED(실패)`

### 참여 결제 상태

- 성공 흐름: `PAID_MOCK(모의 결제 완료)`를 유지하고 별도 주문을 생성
- 실패 흐름: `PAID_MOCK(모의 결제 완료) → REFUNDED_MOCK(모의 환불)`

### 주문 상태

`PENDING(접수) → PROCESSING(제작 중) → COMPLETED(제작 완료)`

## 6. 입력 검증

- 작품 제목, 필명, 소개는 필수다.
- 작품 장르는 1개 이상 8개 이하이며 `NovelGenre` enum 값만 허용한다.
- 작품 생성 시 기본 권(부) `본편`을 자동 생성한다. 권 수는 작품 상세의 권(부) 추가·삭제 결과로 계산하며, 2권부터 회차가 있으면 해당 추가 권을 삭제할 수 없다.
- 부 제목과 부 순서는 필수이며 부 순서는 양수여야 한다.
- 회차 제목과 본문은 필수이며 회차 순서는 양수여야 한다.
- 한 권의 시작·종료 회차는 같은 부에 속하고 연속된 범위여야 한다.
- 권당 목표 글자 수 설정은 두지 않는다. 분량은 안내·협의 문구만 제공한다.
- 펀딩 목표 부수는 10 이상, 금액은 1 이상이어야 한다.
- 펀딩 종료일은 시작일보다 이후여야 하며, OPEN 수정 시 시작+7일 이상·현재 시각 이후여야 한다.
- 이미 마감된 펀딩에는 참여할 수 없다.
- 출판 조건을 만족하지 않은 펀딩은 주문으로 전환할 수 없다.
- 주문 CSV·JSON 내보내기에는 비밀번호·주소·연락처 등 개인정보를 포함하지 않는다.

## 10. 핵심 수동 검증 시나리오

### Lv1 콘텐츠 (현재 구현·검증 대상)

1. 작가가 작품을 만들고 기본 부 `본편`이 자동 생성되는지 확인한다. 필요 시 작품 상세에서 부를 추가한다.
2. 작가가 회차를 작성·공개하고, 독자가 공개 회차만 열람할 수 있는지 확인한다.
3. 독자가 작품 목록·메인 쇼케이스에서 상세·회차로 이동하고, 추천·즐겨찾기·책갈피를 토글한다.
4. 공개 탐색에는 독자·작가의 미공개 작품이 노출되지 않고, 내 작품 관리에는 본인 작품만 표시되는지 확인한다.
5. 추천 전후 작품 `updated_at`과 최신순 카드 순서는 유지되고, 추천순 목록은 변경된 추천 수에 따라 다시 정렬되는지 확인한다.
6. 추천·내 즐겨찾기·검색·필터·페이지 이동 시 화면 위치와 URL 이력이 유지되며 뒤로·앞으로 이동이 동작하는지 확인한다.
7. 메인 인기작·새 회차·완결 벨트의 클릭 이동·드래그·상단 탭 앵커가 동작하는지 확인한다.

### Lv2 펀딩·주문

8. 작가가 작품 상세 부별 「출판 펀딩 시작」에서 목표 부수(최소 10)·금액·기간을 정하고 OPEN한다. 미공개 부·미공개 회차 잔존 시 개설 불가. OPEN은 「펀딩 전체 관리」에서 수정·취소(수요 0만).
9. 독자가 소장본 펀딩에 참여하면 모의 결제가 완료되고 참여 부수가 증가한다.
10. 부 미완결 또는 목표 부수 미달 상태에서 마감하면 실패·모의 환불 처리된다.
11. 부 완결과 목표 부수를 모두 충족한 뒤 마감하면 성공 처리된다.
12. 성공한 펀딩이 책 주문으로 전환되고 작가·독자 화면에서는 제작 상태를 조회한다.
13. 운영자가 주문을 접수·제작 중·제작 완료 순서로 변경한다. (대시보드 1차 구현·시드 검증 가능, 실전환 연동은 Lv2)
14. 운영자 통계 수치가 원본 데이터와 일치하며 주문 CSV·JSON 파일이 같은 조회 조건으로 내려받아진다. (CSV/JSON 1차 구현, 통계는 Lv2)
