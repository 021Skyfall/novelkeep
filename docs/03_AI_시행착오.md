# AI 활용 및 시행착오

## 사용 도구

- Cursor: 과제 안내문 분석, 단계별 의사결정 보조와 환경 확인
- AI가 `winget`과 WSL 명령을 실행해 Docker Desktop 설치를 보조함
- 사용자가 재부팅 후 WSL 알림과 Docker Desktop 실행을 확인함

## 실패와 수정

- AI가 기본 기획안인 `학급알림장`과 권장 기술 조합을 확정 사항처럼 안내함
- 사용자가 아직 정하지 않았음을 지적함
- 주제, 타겟 사용자와 기술 스택을 모두 미확정 상태로 되돌리고 프로젝트 규칙에 명시함
- 사용자가 사업 관점(펀딩·완결 조건·B2B)을 주도하고 AI는 과제 범위와 시장 유사 사례를 교차 검증함
- 시장 최초라고 단정하지 않도록 수정하고, 차별점은 `연재+완결 조건부 펀딩+주문 전환` 통합으로 한정함
- AI가 기존 설치 환경을 우선해 Java 17을 제안했으나, 사용자가 독립 신규 앱에는 최신 LTS를 선호한다고 판단함
- Java 25의 짧은 운영 기간과 외부 라이브러리 호환 위험을 다시 비교함
- 최신성과 검증된 운영 사례의 균형을 위해 Java 21로 최종 변경함
- AI가 인증 제외 조건을 회원 데이터 제외로 과도하게 해석해 첫 ERD에서 회원을 누락함
- 사용자가 작품·펀딩·주문 소유권 문제를 발견해 로그인 없는 최소 회원 엔티티를 추가함
- 권의 시작·종료 번호만 저장하던 초안을 권-회차 연결 테이블 방식으로 수정해 여러 권 구성을 명확히 함
- 사용자가 부 구분을 작가 선택으로 변경해, nullable FK 대신 숨겨진 기본 부 `본편`을 자동 생성하는 방식으로 수정함
- 상태상 값이 없는 공개·환불·완료 시각만 NULL을 허용하고 나머지는 NOT NULL로 정리함
- AI가 역할별 화면 구조를 `각 역할의 첫 기능 화면을 메인처럼 사용`하는 방식으로 해석한 뒤, 다시 `공통 역할 탭으로 전환`하는 방식으로 수정해 사용자의 의도와 연속해서 어긋남
- 사용자가 원한 구조는 `별도 랜딩페이지에서 역할 선택 → 공통 메인 경로와 템플릿 사용 → 세션 역할에 따라 메인 메뉴와 본문을 다르게 렌더링`하는 방식이었음
- AI가 `랜딩페이지`, `메인페이지`, `역할별 기능 화면`의 구분을 먼저 확인하지 않고 문서에 반영해 반복 수정이 발생함
- 이후 사용자가 같은 내용을 여러 번 질문하거나 지시·정정하면 단순 보완이 아닌 AI 시행착오로 판단하고, 원래 해석·사용자 수정·최종 결정·재발 방지를 이 문서에 별도 요청 없이 기록하기로 함
- AI가 서비스 특성 설명에 치우친 딱딱하거나 의미가 불분명한 이름을 반복 제안해 사용자가 원하는 `스위트노벨처럼 짧고 부드러운 이름`과 맞지 않았음
- 사용자가 후보의 방향을 단계적으로 좁힌 뒤 직관성과 발음을 우선해 서비스명을 `노벨킵(NovelKeep)`으로 최종 결정함
- AI가 Lv3 화면·UX 정의까지 합의한 뒤에도 목표 레벨 승인을 남은 절차로 잘못 안내함
- 사용자가 화면 정의가 이미 Lv3 목표를 전제로 한다고 확인해 목표 레벨을 Lv3으로 확정하고, `기획 완료`와 `실제 구현 완료`는 구분해 기록함

## 주제 확정 기록 (사용자 이해·검증)

- 확정 주제: 완결 조건부 웹소설 소장본 펀딩 서비스
- 결제·환불은 모의 상태만 구현
- 기존 웹소설 플랫폼 연동은 확장안으로만 둠
- 기술 스택: Java 21, Spring Boot 4.1.0, Maven, JPA, MariaDB, Thymeleaf, JavaScript, Bootstrap 5.3.8, Docker Compose

## 검증 기록

- Docker Desktop 4.84.0 설치 확인
- Docker CLI 29.6.2 확인
- WSL 기본 버전 2 설정 확인
- Temurin JDK 21.0.12 설치 확인
- JDK 17·25 패키지와 설치 폴더 제거 확인
- `JAVA_HOME`, 사용자 `Path`, `java`, `javac`가 Java 21을 가리키는지 확인
- Apache Maven 3.9.16 공식 배포본 SHA-512 검증 후 설치
- `MAVEN_HOME`, 사용자 `Path`, `mvn -version`과 Java 21 연동 확인
- 실제 컨테이너 실행 검증은 프로젝트 뼈대 생성 후 수행 예정
